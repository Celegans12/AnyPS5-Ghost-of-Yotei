## 1. The interface (`core/libs/prx/libSceAgcDriver/Backend/include/GpuBackend.h`, 189 lines)

One plain C header, two function tables and one factory:
- `Aps5GpuHost`: what AnyPS5 gives the backend. AnyPS5 owns it; it lives until `destroy` returns.
- `Aps5GpuBackendApi`: what the backend gives AnyPS5. The backend owns it.
- `Aps5GpuBackendCreateFunction(host, &api, &backend)`: in-tree it is a direct call; for a DLL its exported name is
  `APS5_GPU_BACKEND_CREATE_SYMBOL` ("Aps5GpuBackendCreate"). The null backend's is `Aps5NullGpuBackendCreate`.

The contract (it is written at the top of the header):
- **Ownership.** Every pointer argument is valid only for the call. Guest addresses stay valid until `memory_unmap`.
  A window's context, extension list and callbacks stay valid from `attach_window` until `release_window`.
- **Errors.** No C++ exception crosses the seam in either direction. Functions return `Aps5GpuStatus`. A backend that
  cannot go on calls `host->fatal`, which reports the message and ends the process.
- **Threads.**
  - `create` runs while AnyPS5's libraries load (under the loader lock): no DLL loads, no threads, no Vulkan.
  - `start` does the heavy setup. AnyPS5 calls it once, before the first submit, window or present.
  - `submit`, `submit_flip`, `suspend_point`, `wait_idle` and `register_shader` run on the guest's own thread,
    directly. `submit` queues and returns; it never waits for GPU work (Z1).
  - `memory_unmap` runs before AnyPS5 changes the pages; `memory_map` and `memory_protect` after the change landed.
  - `protect_guest` (host) is the only way the backend changes guest page protection. AnyPS5 applies it under a
    shared lock that every guest mapping or protection change holds exclusively.
  - `handle_fault` runs in the first vectored exception handler of the process. It returns HANDLED only for pages the
    backend protected itself.
  - The completion callbacks (`raise_interrupt`, `flip_*`, `rendering_wait`, `display_buffer`, `frame_ready`) may be
    called from any backend thread. `raise_interrupt` delivers to the guest's event queues at once (Z2).
  - `present` runs on AnyPS5's presenter thread and calls `presented(ctx)` exactly once. `dump_index >= 0` asks for
    a later `frame_ready(dump_index, BGRA8 pixels)`.

| spec item | host → backend (`Aps5GpuBackendApi`) | backend → host (`Aps5GpuHost`) |
|---|---|---|
| queue submits | `submit(queue, dwords, count)` | |
| flip requests | `submit_flip(flip)` (CPU flips) | `flip_reserve`, `flip_wait_room`, `flip_ready`, `flip_cancel` (in-stream flips) |
| completion signals | | `raise_interrupt(event_id = queue, context_id)`; labels are plain stores into guest memory |
| memory notifications | `memory_unmap`, `memory_map`, `memory_protect`, `host_write_begin/end`, `host_read` | `backing_view`, `direct_mapping`, `mapping_generation`, `protect_guest` |
| fault hook | `handle_fault(address, access)` | |
| VideoOut presentation | `attach_window`, `release_window`, `present` | `display_buffer(handle, index)` (the one VideoOut method), `rendering_wait`, `frame_ready` |
| lifecycle, services | `start`, `shutdown`, `destroy`, `suspend_point`, `wait_idle`, `register_shader` | `log`, `fatal`, `read_tsc`, `tsc_frequency`, `process_time_us/counter`, `is_guest_thread`, `app_title_id`, `app_content_version` |

## 3. Design choices

### 3.1 Where the switch lives, and the cost with it off
- One value for the whole process, read in libc (the lowest library) at its static init and cached; libkernel and
  libSceAgcDriver ask libc once and cache it in a function-local static.
- With the switch off, every changed path costs one cached-bool test, and the libc mapping functions an atomic load of
  a null observer. `Driver`, `WindowsMappings::Map(resident=true)`, the write watch and the section pool are exactly
  today's.
- The shader-cache SourceVersion is unchanged, `22c401ea7ca3796f` [M build-local generated header]: libSceAgcDriver's
  own files are only checked by the cache-key guard, not hashed. So T1 runs warm.

### 3.2 The old driver is never constructed under kyty
- `Driver::Driver()` throws a `logic_error` when the switch is on. Every entry that reached `Driver::Get()` is routed
  first, so a missed path fails loudly instead of building the old driver's 8.8 GB import (both would not fit in
  32 GB).
- The ABI-resolution hooks and `ShaderPreparationScope` (used by libSceAgc's LinkShaders, InterpolantMapping,
  PrimState) are no-ops. Replay/capture internals (`SaveQueueStates`, `Settle`, `Quiescent`, `SerialProgress`,
  bindless priming) throw "not supported with APS5_GPU_BACKEND=kyty". EOP flips throw, as the spec says (Yotei does
  not call them). Diagnostics counters return 0.

### 3.3 The null backend is a null command processor, not just a counter
- Counting alone would stop the game at its first GPU wait, before any flip. So the stub walks each submission on the
  submitting thread and completes, with no GPU work:
  - the walk covers type-3 headers and type-2 fillers, and follows INDIRECT_BUFFER 0x3f. Chains (bit 20) replace the
    cursor, calls push, 8 deep, with a 128 M-dword budget. v4c found q0's 30-dword DCB chaining 147-157 buffers per
    frame (~235 k dw), so without this the flip and the labels are never seen;
  - `RELEASE_MEM` (0x49): the label write (32/64-bit data, or a 100 MHz reference clock for DATA_SEL 3) and the
    interrupt for INT_SEL 1/2/4 with Kyty's context id (`packet[7] & 0x07ffffff`), event id = queue;
  - `WRITE_DATA` (0x37) to memory;
  - the flip NOP (`0xc004105c`, R_FLIP): `flip_reserve` → `flip_ready` → interrupt (queue, 0), as Kyty does after a flip;
  - the rendering wait NOP (`0xc0021018`, either length): `rendering_wait`.
- It counts every opcode (an opcode census for free, see §4) and logs a count line every 10 s.
- This exercises every host callback M1b's Kyty will use: interrupts to event queues, flips into VideoOut, label
  stores, rendering waits, frame dumps.
- What it cannot do: dispatches and draws produce nothing, so anything the game reads back from GPU work is zero or
  stale. A boot that goes wrong later is expected and says nothing about the adapter.

### 3.4 Event queues stay on the AnyPS5 side
- The spec routes `sceAgcDriverAddEqEvent` to Kyty's `Sync::AddEqEvent`. Here the registration stays in AnyPS5
  (Kyty's trigger semantics: `fflags++`, `data = context id`, every trigger kept in `pendingEvents`), and the backend
  raises interrupts through `host->raise_interrupt(event_id, context_id)`.
- Same behaviour for the guest, no kernel types across the seam, and Kyty's `sync.cpp` patch shrinks:
  `RenderContext::TriggerInterrupt` calls the host, and `Sync::AddEqEvent/DeleteEqEvent` are not used.
- Z2: the trigger runs on the calling backend thread, straight into `EqueueTriggerEvent`, with only the adapter's
  registration mutex (copied out, max 16 registrations per event) in front.

### 3.5 Flips
- In-stream and CPU flips reserve with `IVideoOutput::Reserve` (unlimited), as the old driver does
  (`Submission.cpp` l.313); `TryReserve` is the EOP-flip path and would refuse unregistered buffers that the old path
  presents black. `APS5_GPU_FLIP_QUEUE_FULL` stays in the interface for backends that want it; AnyPS5's host never
  returns it.
- `flip_ready` calls `IFlipRequest::GpuReady` with a fresh `FrameTiming`; VideoOut's presenter then calls
  `AgcDriverPresentBuffer`, which reaches `present`.

### 3.6 Guest memory
- Every guest arena change is bracketed in libc (`BackendChange`): begin = `memory_unmap` (only if the range had
  committed pages) then the adapter's lock taken exclusive; end = lock released then `memory_map`/`memory_protect`.
  Guest mprotect spans `GuestArenaSetProtection` … `GuestArenaEndSetProtection`, so the lock covers libkernel's own
  `VirtualProtect` loop. The lock is re-entrant per thread (a commit inside an mprotect).
- Host I/O: AnyPS5's existing `HostWrite`/`GuestArenaBeginHostWrite` and `GuestArenaPrepareHostRead` hooks go to
  `host_write_begin`/`host_read`; a new end hook goes to `host_write_end`.
- The AGC driver block is 2 MiB of direct memory at `0xfe0000000` (memory type 12, protection 0x33, as Kyty), mapped
  through a new libkernel export because the address sits in the arena's system-reserved hole; Kyty's descriptor at
  +0x40000, function table at +0x40060 and ordered-count validator at +0x40100.
- `AgcDriverCheckGuestMemory` under kyty: `VirtualQuery`, and a page the backend write-protected still counts as
  writable when the guest's own protection says so. `AgcDriverStoreGuestLabel`: check, then a plain release store
  (a store into a tracked page faults and the backend serves it).

### 5.2 Open items on AnyPS5's side
- `is_guest_thread` returns −1 (unknown). Kyty uses `PthreadSelfOrNull` once (`renderContext.cpp` l.109). A small
  libkernel export is needed.
- Mappings made before libSceAgcDriver loads are not reported to the backend (Kyty's own kernel also drops mappings
  before its GPU exists). Guest code runs only after every library has loaded, so this covers guest mappings. Add a
  replay only if M1b finds an early host-side range Kyty needs.
- A guest mapping change that fails after `memory_unmap` was sent leaves the backend thinking the range is gone
  (conservative). A nested change (a commit inside an mprotect) calls `memory_unmap` while holding the lock;
  harmless for the null backend, and to watch with Kyty's `UnmapMemory`, which waits for the GPU thread.
- `SetTFRing` / `SetHsOffchipParam` stay AnyPS5's on both paths. Kyty only records the values (`libs/agc.cpp`
