### Functional

- [Frame replay](../../../core/libs/prx/libSceAgcDriver/tools/FrameReplay.cpp) (libSceAgcDriver) orders the calls of different captured threads only by their start (a call starts once every earlier call has started), so the driver sees a schedule the title could have produced, not necessarily the one it did. CPU stores a title made from threads that never call the driver are known only by the next recorded call, so the replay applies them early or late when a GPU wait needs them and derives a value from the wait's reference when no recorded store satisfies it (`of_them_synthesized`). Pacing compares the number of submissions in flight, not what they hold. Prologue registrations of shaders whose memory the title reused after registering them fail and are counted (`stale_registrations`). The title's image range must be free in the replaying process, so the tool is linked at a high image base on Windows.
- [Frame replay pacing](../../../core/libs/prx/libSceAgcDriver/tools/FrameReplay.cpp) (libSceAgcDriver) - pacing and the drain count a running queue as progress for up to 10 minutes, so a queue that never finishes or parks holds the replay that long before it gives up. A memory delta waits only until no queue runs, so a submission another captured thread made before the delta can still reach the driver after it.

- [Initial stencil state](../../../core/libs/prx/libSceAgcDriver/Execution/include/QueueState.hpp) uses zero for `DB_STENCIL_CONTROL`, `DB_STENCILREFMASK` and `DB_STENCILREFMASK_BF` (context `0x10b`-`0x10d`), including after `CLEAR_STATE`. The public V0, V4, V5 and V7-V11 [register-default tables](../../../core/libs/prx/libSceAgc/Command/include/RegisterDefaultsData.hpp) supply these values. Linux's [GFX10 clear-state table](https://github.com/torvalds/linux/blob/master/drivers/gpu/drm/amd/amdgpu/clearstate_gfx10.h) agrees on the control register but uses `0x01000000` for the reference masks; the console reset values have not been measured. Planet Coaster (PPSA01736 v01.017) enables stencil tests without writing the control register.
- [Initial depth and stencil planes](../../../core/libs/prx/libSceAgcDriver/Execution/include/QueueState.hpp) - the console's reset values of `DB_Z_INFO` and `DB_STENCIL_INFO` (context `0x010`-`0x011`) are not measured. Both start, and return after `CLEAR_STATE`, at zero (formats `INVALID`), the value of Linux's [GFX10 clear-state table](https://github.com/torvalds/linux/blob/master/drivers/gpu/drm/amd/amdgpu/clearstate_gfx10.h). The public [register-default tables](../../../core/libs/prx/libSceAgc/Command/include/RegisterDefaultsData.hpp) write `0x80000180` and `0x20000180` instead, also with formats `INVALID`; of their other bits, only `TILE_STENCIL_DISABLE` would change a result: the HTILE layout of a multisampled depth plane whose `DB_STENCIL_INFO` was never written.

- [`APS5_THREAD_PRIORITY=rt`](../../../core/libs/prx/libSceAgcDriver/Execution/src/ThreadPriority.cpp) (libSceAgcDriver) lowers the process's hard `RLIMIT_RTTIME` when it is above `APS5_THREAD_RTTIME_US` or rtkit's `RTTimeUSecMax`, because [rtkit](https://github.com/heftig/rtkit/blob/c295fa849f52b487be6433e69e08b46251950399/rtkit-daemon.c#L592-L637) (`verify_process_rttime`) reads the hard limit from `/proc/<pid>/limits` and refuses real-time scheduling when it is higher. An unprivileged process cannot raise the hard limit again, so it stays lowered for the process and its threads even when rtkit then refuses the request (burst limit, user or start-time checks) and the thread throws. rtkit's `MaxRealtimePriority` and `RTTimeUSecMax` are read first, so an unreachable rtkit or a priority above its maximum leaves the limit untouched. The lowered limit only matters for threads that later run under a real-time policy

- [BT.2100 PQ display buffers](../../../core/libs/prx/libSceAgcDriver/Execution/include/PqToSdr.hpp) (libSceAgcDriver, libSceVideoOut) - pixel formats `0x8100070422000000` and `0x8100070400000000` are taken as 10:10:10:2 texels with BT.2020 primaries and the SMPTE ST 2084 transfer, red or blue in the low bits, as [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOutTypes.cs) names them (`Rgb10A2Bt2100Pq`, `Bgr10A2Bt2100Pq`) and [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/59183dbfa81ed7efdff6069177fed50de0552725/src/graphics/host_gpu/renderer/image/imageInfo.h) maps the first; PPSA01317 registers display buffers of the first when its output reports HDR. With HDR output they are presented unchanged through an HDR10 swapchain (`VK_COLOR_SPACE_HDR10_ST2084_EXT`, 10-bit, with `VK_EXT_hdr_metadata`); otherwise they are converted to 8-bit sRGB: ST 2084 EOTF, BT.2020 to BT.709 primaries with negative components clipped, a luminance tone map and the sRGB encoding. The tone map is ours: min(203 nits, white level) is SDR white (the BT.2408 HDR reference white), luminance passes unchanged up to 0.75 of it and an extended Reinhard shoulder above reaches 1.0 at the white level, the peak sceSystemServiceGetHdrToneMapLuminance last reported to the title (or the current one when it never asked), since titles read it once. How a console shows such a buffer on an SDR display is unknown. Alpha is opaque.

- [`sceAgcDriverUnknown_yuO_plus_lNrj_plus_Do` (NID `yuO+lNrj+Do`)](../../../core/libs/prx/libSceAgcDriver/Export.cpp) (libSceAgcDriver) - unnamed in every published inventory and in the aerolib NID database; demanded by ACS (PPSA20397). Firmware 4.03 body at RVA `0x8f0`: returns `0x8A6D0003` unless the first argument is 1, then forwards the caller's second argument register untouched into `sceKernelDebugRaiseException(0xA002030A)` and returns `0x8A6D0005` when that raise fails, `0x8A6D0003` when it succeeds. Firmware `sceKernelDebugRaiseException` (libkernel `0x26670`) itself rejects a nonzero second argument with `0x80020016` before posting. Our [sceKernelDebugRaiseException](../../../core/libs/prx/libkernel/System/src/Exception.cpp) is a log-only void stub, so the raise path here is modeled as always posting and returning `0x8A6D0003`; the console's exception-delivery semantics (whether the raise traps into a debugger or fault handler before returning) are unmeasured.

- [Graphics state suppression ownership](../../../core/libs/prx/libSceAgcDriver/Graphics/include/Context.hpp) (libSceAgcDriver) - `Context::Function`, `Context::Resolved` and the device setup lookup reject a graphics pipeline bind, a tracked dynamic state command, `vkCmdBindShadersEXT` or `vkCmdExecuteCommands` by name at compile time, and the device table hands those entry points only to `CommandState` and `Context::BindComputePipeline`. `CommandState` cannot be copied or moved, and `FunctionName` keeps its name private, so neither a duplicate tracker nor an edited name can bypass the check. Two routes stay open because the type system cannot see them: a raw `deviceProc` lookup cast to the function type, and a second `CommandState` begun on a recorder batch's command buffer (`Begin` is public for presentation, the overlay and tests, which record their own command buffers).

### Opt-in draw paths

- [Multi-submit count overflow and buffer validation](../../../core/libs/prx/libSceAgcDriver/Submit/src/Dcb.cpp) (libSceAgcDriver) - whether the console driver imposes an architectural submission packet limit or allows null buffer pointers with non-zero sizes in multi-submit arrays is unmeasured; AgcDriver::SubmitMany validates count against 32-bit pointer array bounds overflow and rejects null addresses for non-empty command buffers with a runtime exception.
- [Frame replay on Linux needs the kernel write watch](../../../core/libs/prx/libSceAgcDriver/tools/FrameReplay.cpp) (libSceAgcDriver) - `agc_frame_replay` registers every captured watched range with the guest write watch, which needs `PAGEMAP_SCAN` and asynchronous userfaultfd write protection (Linux 6.7 or newer, and kernel headers that define them at build time). Without them the replay stops with the reason (the failing build, kernel feature or ioctl, and the errno of a failed call or registration) and does not fall back to comparing, because native multisample depth and the page-wise `--repeat` reset need the watch. Closes when: replay has a measured comparison path for ranges the watch cannot cover.
