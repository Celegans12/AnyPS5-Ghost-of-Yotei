# libSceAgcDriver

## add Opt-in draw paths

- [Batch fence status by serial](../../../core/libs/prx/libSceAgcDriver/Graphics/src/Recorder.cpp) (`APS5_REAP_BY_SERIAL`) - opt-in and written without a build: not compiled, not run and not measured. The serial only refuses; a batch it accepts still costs one `vkGetFenceStatus`, and a batch whose fence is signaled is retired only once the progress watcher thread has woken, so its completion actions (copied write-backs, completion labels, end-of-pipe interrupts) can run one thread wake-up later than without the switch. The recorder test covers a recorder without a timeline only; the timeline path runs in three label order tests. Closes when: built, its tests pass and a title is measured with it and with `APS5_VERIFY_REAP_BY_SERIAL`.
- [Label marks per batch](../../../core/libs/prx/libSceAgcDriver/Execution/src/GuestMemory.cpp) (`APS5_LABEL_MARKS_PER_BATCH`) - opt-in and written without a build: not compiled, not run and not measured. A CPU write to a label's 64 KiB block made between two labels of one batch is no longer collected at the second label: it stays in the write watch until the next collect of its page, which stamps it as a CPU write with a later generation than the label's. Readers that collect their range before they trust a stamp see it; a reader that relied on the collect made at the label does not, and none was searched for beyond the tracker test. Only labels stored on the GPU and noted in the label table take the path; labels stored behind a completion and larger stores collect as before. Closes when: built, its test passes and a title is measured with `APS5_VERIFY_LABEL_MARKS`, whose count of collects that found a write says how often the difference exists.
- [Held submits at a submission's end](../../../core/libs/prx/libSceAgcDriver/Execution/src/Driver/Queues/QueueWorker.cpp) (`APS5_SUBMIT_GROUP`) - opt-in and written without a build: not compiled, not run and not measured. On the console a label is visible once the GPU reached it; with the switch a label, a copied write-back or a GPU result of a held batch reaches guest memory up to `APS5_LABEL_FLUSH_US` later than without it, which a title that polls the label from the CPU observes, and the GPU starts the held work as much later. The driver cannot see such a poll, so the hold is decided on the committer's queue alone. A batch is held only at a submission end committed by the draw pipeline; the submits made on a label's deadline by other threads are unchanged. Closes when: measured in a title, with the latency of polled labels compared.
