# libSceSaveData.native

## add Functional

- [sceSaveDataUmount2](../../../core/libs/prx/libSceSaveData.native/Export.cpp) (libSceSaveData.native) - modes `0x10000` (`SAVE_DATA_UMOUNT_MODE_BACKUP`) and `0x10001` (`SAVE_DATA_UMOUNT_MODE_BACKUP | SAVE_DATA_UMOUNT_MODE_BACKUP_FORCE`) synchronously copy the save backup and queue and deliver a `SAVE_DATA_EVENT_TYPE_UMOUNT_BACKUP` (`1`) event identically to `sceSaveDataUmountWithBackup`, without distinguishing forced backups from ordinary backup unmounts or skipping unmodified saves. Mode `0` and mode `1` (`SAVE_DATA_UMOUNT_MODE_BACKUP_FORCE` without `SAVE_DATA_UMOUNT_MODE_BACKUP`, which a PS5 title passes before its title screen) unmount without backing up or queuing an event, as KytyPS5 (PS5, `src/libs/libSaveData.cpp`) backs up only on bit 16. Any other bit is reported once on stderr and ignored, so a mode with an unknown bit unmounts, and backs up when bit 16 is set; what those bits do on a console is not known. Unlike `sceSaveDataUmountWithBackup`, `sceSaveDataUmount2` does not require `sceSaveDataInitialize3` before returning `SAVE_DATA_ERROR_NOT_MOUNTED`. Closes when: measured on a PS5. Labels: console, tested.
