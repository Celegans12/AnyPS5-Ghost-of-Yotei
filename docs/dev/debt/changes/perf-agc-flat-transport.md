# libSceAgcDriver

## add Opt-in draw paths

- [Flat transport between the pipeline stages](../../../core/libs/prx/libSceAgcDriver/Execution/include/Driver/Draw/FlatTransport.hpp) (`APS5_FLAT_TRANSPORT`) - opt-in, written without a build: not compiled, and not run in its tests, on a replay of captured frames or in a title. An overlap query reads one record per queued item instead of the short list of distinct written ranges the locked queue keeps, so a query on a full queue may cost more than the uncontended lock it replaces; the `[transport]` line counts the records read and nothing is measured. An item with more than 6 written ranges, 12 read ranges or 16 label bytes is answered under a mutex; how often that happens in a title is counted and not measured. Producers still exclude each other with a spin flag, which the driver never contends but a test with several producers can. Closes when: measured in a title.
- [What the flat transport leaves allocated and locked](../../../core/libs/prx/libSceAgcDriver/Execution/src/Driver/Draw/DrawPipeline.cpp) (`APS5_FLAT_TRANSPORT`) - the commit of every item is still a `std::function` its caller builds, for a draw around a heap block (`Draw.cpp`). With `APS5_FINISHER_THREADS` above 1 the pool still takes its mutex to queue, start and retire each job, allocates a slot per job and a closure and a heap block per item a job holds back, and wakes every waiter at each retirement; only its overlap queries stopped taking the mutex. The count of outstanding finisher jobs is still two atomic updates per job.
