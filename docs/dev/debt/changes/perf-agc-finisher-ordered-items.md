# libSceAgcDriver

## add Opt-in draw paths

- [Ordered items behind the draw finisher](../../../core/libs/prx/libSceAgcDriver/Execution/src/Driver/Draw/DrawPipeline.cpp) (`APS5_DRAW_PIPELINE`) - an item with read ranges (a DMA copy) still drains the finisher instead of being relayed through it: `DrawPipeline::HeldReads`, which holds a write-back back over memory a queued item reads, sees the committer's queue alone. A store the finisher still holds answers `StoredBytes` with `Unknown`, so a capture over it drains the pipeline. The finisher's pending list answers only the thread that queued it; another thread sees a relayed item once the committer's queue holds it, as it sees a handed-over draw. `APS5_NO_FINISHER_RELAY` drains for every item.
- [Submission ends behind the draw finisher](../../../core/libs/prx/libSceAgcDriver/Execution/src/Driver/Packets/PacketExecution.cpp) (`APS5_DRAW_PIPELINE`) - the worker starts the next submission, or goes idle, while the finisher still holds draws of the previous one. A finisher job reads a copy of the submission holding only its serial, queue and shader registry (`DrawTail::handed`); code added to the finisher's half of a draw gets every other field empty. The worker's idle store of pending results (`StoreIdleResults`) is not ordered against the finisher's captures, as it is not against the committer's queue. `APS5_NO_RELAYED_SUBMISSION_END` drains at every submission end.
