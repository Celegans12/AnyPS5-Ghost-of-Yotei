# libc

## add Functional

- On Windows [page tracking](../../../core/libs/prx/libc/include/WindowsPageTrack.hpp) (libc, `APS5_PAGE_TRACK=1`, off by default) write-protects cold 64 KiB blocks of private and resident guest memory. A kernel write into such a block outside `GuestArena::HostWrite` fails with `ERROR_NOACCESS`; a read still pending when its block is protected lands unseen, as it already escapes the write watch. Only blocks inside one host allocation are protected, so memory committed in 16 KiB granules stays on `GetWriteWatch`, and so does every imported block, although the GPU only reads most imports. Frames are counted by the AGC driver; without it nothing is protected. Measured on the replay bench on an earlier base only, not on this one and not in a running title.
- [Page tracking](../../../core/libs/prx/libc/include/WindowsPageTrack.hpp) (libc) trusts the arena APIs for the protection of a block: it protects a block only if no `Commit`, `Protect` or `SetProtection` gave it another protection, and checks the host protection only under `APS5_VERIFY_PAGE_TRACK=1`. Code that changes the protection of guest memory with `VirtualProtect` directly must call `GuestPageTrackKeepOpen` first.
- [Page tracking](../../../core/libs/prx/libc/include/WindowsPageTrack.hpp) (libc) cannot serve a thread that runs on a stack the arena does not know: if that stack lies in a protected block, Windows cannot push the exception frame of the write fault and ends the process without a report. Registered guest stacks (main stack, fibers, user contexts) are pinned and never protected, host thread stacks lie outside the arena, and only memory the driver collects is ever protected. Not observed.
- [Page tracking under collects outside the mapping lock](../../../core/libs/prx/libc/include/WindowsMappings.hpp) (libc) - with `APS5_PAGE_TRACK=1` a collect releases the mapping lock around the `GetWriteWatch` call of each run of unprotected blocks, as without it, and reads the state of the next block again once it holds the lock; the protection of a block, the reset of its write watch and the read of the pages that reset reports keep the lock, 64 KiB at a time. Two collects that overlap in a 64 KiB block while one is outside the lock can each leave the other pages to report, which the driver's tracker excludes by walking a block from one thread at a time; a caller that does not can meet `owned write collection exceeds its page buffer`. The page tracking tests were written for collects that keep the lock and have not been built or run on this base.
