# kyty

## add Functional

- [Merged hull programs](../../../core/kyty/graphics/shader/recompiler/Tessellation.cpp) (kyty backend) differ from the console: a wave-mask branch (`s_cbranch_exec[n]z`, `s_cbranch_vcc[n]z`) and an SCC taken from a mask operation test the invocation's own lane, so a block the console runs for the wave, scalar instructions included, can be skipped; `v_readfirstlane_b32` returns the invocation's own value; invocation i holds control point min(i, inputs - 1) of its patch, where hull lane i keeps local lane i's registers; the patch field of `v1` and `v3` do not count the patches of a wave; a patch constant read back by an invocation other than 0 is not ordered after its store. The register layout (`s3`, `v0`-`v5`) is not measured on hardware. A registered type 3 program in the LS slot runs whole in the tessellation control stage, one invocation per output control point.
- [Merged hull lowering](../../../core/kyty/graphics/shader/recompiler/Tessellation.cpp) (kyty backend) stops on programs the default backend runs: no LDS write, 16-bit LDS accesses, any `s_swappc_b64`, a program in the HS slot, LDS written again after an `s_barrier` while another control point's record is read (even with a second barrier before the readers), a control point store that only a branch with a constant condition places after an off-chip read of another control point, and addresses Kyty's decode-level layout pass does not model; some of these stops print a condition, not a message. Vertex loads in the local part, wave32 and fewer input than output control points are untested. No test goes through Kyty's renderer ([MergedHull.cpp](../../../core/libs/prx/libSceAgcDriver/KytyShim/tests/MergedHull.cpp) draws with a pipeline of its own), and none covers `KYTY_TESSELLATION=0`.
