# libSceAgcDriver

## add Opt-in draw paths

- [Draw blocks for stage buffers](../../../core/libs/prx/libSceAgcDriver/Graphics/src/DrawBlock.cpp) (`APS5_DRAW_BLOCK`) - opt-in. Every buffer range of at most `APS5_CORE_RING_MAX` bytes a served stage reads is copied from guest memory into the block ring at each commit, and nothing remembers a copy between two draws of a run. A larger range is read by address from a buffer cache mirror or in place from a host import; the mirror path is compiled and not exercised by a test or a bench run (the bench ran without the buffer cache), and a large range with neither is still copied whole per draw. A copied range with a recorded GPU write, a queued store or a queued label over it is read after a wait for that work, which ends the open batch early. An unreadable range becomes an absent buffer that reads as zeros where the descriptor path rebuilds the draw.
- [Stages left outside draw blocks](../../../core/libs/prx/libSceAgcDriver/Execution/src/Driver/Draw/DrawCapture.cpp) (`APS5_DRAW_BLOCK`) - only direct draws of one vertex and one fragment stage ask for block modules; indirect draws, rectangle lists and draws with tessellation, geometry or mesh stages keep descriptors, as does a stage with a written or atomic buffer, a descriptor read on the GPU, an image table, a poison record or a push slice too full for the section address. A draw may mix a block stage and a descriptor stage, and then still rewrites the sets of the descriptor stage. The compiled words of a block stage are copied at the commit from what the draw cache holds; the flat walk of the tape (`SrtTape::RunInto`) and the block writer (`Core/src/BlockWriter.cpp`) are built and tested but not called by a draw yet.
- [Verification of draw blocks](../../../core/libs/prx/libSceAgcDriver/Graphics/src/DrawBlock.cpp) (`APS5_VERIFY_DRAW_BLOCK`) - compares a section with the words and the guest bytes it was written from, read again at the same commit; it does not build the descriptor sets of the same draw and cannot see a module that reads the section wrongly, which only a pixel comparison shows. A title that rewrites a range between the copy and the second read throws although both paths would be right. No test forces a wrong entry through the driver to prove the verification throws; the comparison itself is covered without a device in `agc_core_block_verify`.
- [Memory of the block ring](../../../core/libs/prx/libSceAgcDriver/Core/src/DrawBlockHost.cpp) (`APS5_DRAW_BLOCK`) - the ring chunks are host-visible, host-coherent buffers of the default memory type of `Graphics::Buffer`; the cost on the GPU of reading sections and copies there by address, against a device-local copy per batch, is not measured by a probe of its own.
- [Draws taken by the core run](../../../core/libs/prx/libSceAgcDriver/Core/src/Front.cpp) (`APS5_CORE_RUN`) - opt-in. Plans and variants are kept until the process ends (`RunPlans` has no collection), and a variant whose image set slot is taken is taught again. A plan covers only one vertex and one fragment stage compiled for draw blocks, without merged programs, user data continuations, written buffers, storage images or image tables; a state the classic path never captured in this run is never taught. The decode thread walks with the tape's `Run` (three vectors per stage, a guarded copy per word) and walks again when the committer retired an item meanwhile. The committer records a taken draw through the classic recipe path with its proofs, input copies and descriptor sets; only the image set cache and the plan table are used, with a constant proof. No test drives a taken draw through the driver; `APS5_VERIFY_CORE_RUN` and the bench's image comparison are the only checks.
- [Flat draws of the core run](../../../core/libs/prx/libSceAgcDriver/Core/src/Front.cpp) (`APS5_CORE_FLAT_DRAW`) - opt-in. Every taught variant is kept until the process ends, and a queued record names it by a bare pointer. The flat front still walks with the tape's `Run`, one guarded copy per word: on both measured titles nearly every block layout has no flattened word, so `WriteDraw` (`Core/src/DecodeDraw.cpp`) is called by no draw. The record goes to a ring in ordinary memory and is copied into the stage results, then into the block ring. Freshness is proven by the queue queries of the old path; the block ledger is not used, and with `APS5_FLAT_TRANSPORT` the walk is repeated. `Core/src/FrontMemo.cpp`, `APS5_CORE_FRONT_COPIES` and `Core/src/TailMeter.cpp` are built and tested but called by nothing. No test drives a flat draw through the driver; `APS5_VERIFY_CORE_RUN` and the bench's image comparison are the only checks.
- [Light lane of the packet loop](../../../core/libs/prx/libSceAgcDriver/Execution/src/Driver/Packets/PacketExecution.cpp) (`APS5_CORE_LIGHT_LANE`) - opt-in. A typed NOP, an index type packet and every packet outside the lane's list end a run and take the heavy path. Inside a run the label flush check, the failure check and the reaping of completion labels happen once, so a pending label is submitted up to one run of 64 packets later than on the heavy path. A register list is executed from the copy taken at submission without the pipeline overlap query the heavy path makes for it. The lane builds no timer, and with the switch the heavy path gives a frame timing context to one packet in `APS5_CORE_CLOCK_PERIOD`: frame timing lines then under-report packet stages. `APS5_VERIFY_CORE_LIGHT_LANE` proves the class-based skips on the titles it is run on; no test without a device covers the lane beyond `agc_core_decode_lane`.
- [Driver zone walk of the flat front](../../../core/libs/prx/libSceAgcDriver/Core/src/Front.cpp) (`APS5_CORE_TAPE_ZONE`) - opt-in and not proven. On one of the two measured titles the comparison of `APS5_VERIFY_CORE_RUN` threw in two runs out of three, at the same draw during warm-up, because the variant chosen from the zone held another recipe template than the classic path; the third run and both runs of the other title compared several hundred thousand draws without a difference. The cause is not found: either the zone leaves out something the walk results tell apart, or the template comparison races with a template rebuilt during warm-up. Until it is, the switch stays off by default.
