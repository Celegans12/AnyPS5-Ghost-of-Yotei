# libSceAgcDriver

## add Opt-in draw paths

- [Draw blocks for stage buffers](../../../core/libs/prx/libSceAgcDriver/Graphics/src/DrawBlock.cpp) (`APS5_DRAW_BLOCK`) - opt-in. Every buffer range a served stage reads is copied from guest memory into the block ring at each commit, whatever its size: the mirrors of the buffer cache and the host imports have no device address, so a large read-only range that descriptors bind in place or from a mirror is copied again for every draw, and nothing remembers a copy between two draws of a run. `APS5_CORE_RING_MAX` is read and changes nothing yet. A range with a recorded GPU write, a queued store or a queued label over it is read after a wait for that work instead of being read in place by the GPU, which ends the open batch early. An unreadable range becomes an absent buffer that reads as zeros where the descriptor path rebuilds the draw.
- [Stages left outside draw blocks](../../../core/libs/prx/libSceAgcDriver/Execution/src/Driver/Draw/DrawCapture.cpp) (`APS5_DRAW_BLOCK`) - only direct draws of one vertex and one fragment stage ask for block modules; indirect draws, rectangle lists and draws with tessellation, geometry or mesh stages keep descriptors, as does a stage with a written or atomic buffer, a descriptor read on the GPU, an image table, a poison record or a push slice too full for the section address. A draw may mix a block stage and a descriptor stage, and then still rewrites the sets of the descriptor stage. The compiled words of a block stage are copied at the commit from what the draw cache holds; the flat walk of the tape (`SrtTape::RunInto`) and the block writer (`Core/src/BlockWriter.cpp`) are built and tested but not called by a draw yet.
- [Verification of draw blocks](../../../core/libs/prx/libSceAgcDriver/Graphics/src/DrawBlock.cpp) (`APS5_VERIFY_DRAW_BLOCK`) - compares a section with the words and the guest bytes it was written from, read again at the same commit; it does not build the descriptor sets of the same draw and cannot see a module that reads the section wrongly, which only a pixel comparison shows. A title that rewrites a range between the copy and the second read throws although both paths would be right. No test forces a wrong entry through the driver to prove the verification throws; the comparison itself is covered without a device in `agc_core_block_verify`.
- [Memory of the block ring](../../../core/libs/prx/libSceAgcDriver/Core/src/DrawBlockHost.cpp) (`APS5_DRAW_BLOCK`) - the ring chunks are host-visible, host-coherent buffers of the default memory type of `Graphics::Buffer`; the cost on the GPU of reading sections and copies there by address, against a device-local copy per batch, is not measured by a probe of its own.
