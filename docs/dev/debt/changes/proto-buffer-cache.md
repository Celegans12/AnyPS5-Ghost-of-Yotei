# libSceAgcDriver

## add Opt-in draw paths

- [Buffer cache](../../../core/libs/prx/libSceAgcDriver/Graphics/src/BufferCache.cpp) (`APS5_BUFFER_CACHE`) - opt-in and written without a build: it has not been compiled, run in its test or measured in a title. It serves only the index and vertex ranges of draws on drivers that copy draw inputs; the stage buffers, constant buffers, zero-padded vertex fetches, expanded and compacted index buffers keep the snapshot path. Closes when: built, its test passes and a title is measured with it.
- [Buffer cache dirtiness](../../../core/libs/prx/libSceAgcDriver/Graphics/src/BufferCache.cpp) (`APS5_BUFFER_CACHE`) - until the page-protection tracking is handed to `BufferCache::SetArmedBlocks`, every lookup still collects the write watch of its range, so the system calls per draw are those of the snapshots it replaces. The entries for arming at upload, for the pages written since a token and for the reason a block stays unarmed are called as the cache expects them, not as the tracking defines them: their contract is checked against scripted functions only. A block is asked to be armed only when it is uploaded, so a block the write tracker keeps clean while it cannot be armed is not asked again until it is written. A change of the guest allocation registry marks every block of a mirror stale, whichever range changed. Closes when: the entries are bound to the page tracking, armed block tokens answer the lookups in a title and an unmap invalidates its own range.
- [Buffer cache stream](../../../core/libs/prx/libSceAgcDriver/Graphics/src/BufferCache.cpp) (`APS5_BUFFER_CACHE`) - a block is left to the per-frame stream only when the source calls it volatile, which the write tracker alone never does: without the page tracking's reasons no block is streamed. The rest of 128 batches before a block is asked for again is not measured, a streamed range is copied at every draw that reads it even when two draws of a frame read the same bytes, a streamed index range is scanned for its bounds at every draw, and ranges above 1 MiB keep the snapshot path. `APS5_NO_BUFFER_CACHE_STREAM=1` keeps such blocks in their mirrors.
- [Buffer cache imports](../../../core/libs/prx/libSceAgcDriver/Graphics/src/BufferCache.cpp) (`APS5_BUFFER_CACHE`) - the ranges the cache serves stay host-imported by the other requesters, so their blocks cannot be armed. A range a recorded GPU write, a label or a queued store overlaps, counted per page-rounded range, is refused and takes the snapshot path. Closes when: imports are withheld from the blocks the cache serves.
- [Lazy map imports](../../../core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp) (`APS5_LAZY_MAP_IMPORTS`) - opt-in, not built, not measured. It only stops the import made at a mapping: the first consumer that asks for an import of a range still imports the whole run or 64 MiB window around it, under the GPU lock, so vertex memory that shares a run with a buffer the GPU writes or a descriptor binds is imported as before, and a first use pays the import a mapping paid ahead. Which requesters still import the memory the buffer cache serves is unknown until a title is run with it. Closes when: a title shows the share of imported blocks among those the cache serves, and imports are cut to the blocks their requester needs.
- [Buffer cache pending draws](../../../core/libs/prx/libSceAgcDriver/Graphics/src/BufferCache.cpp) (`APS5_BUFFER_CACHE`) - a written page that a draw of an unfinished batch reads is not uploaded in place: the range is refused until that batch ran, unless the page still equals guest memory. A title that rewrites a page between two draws of one batch therefore keeps the snapshot path for the later draw. Pages are uploaded into host-visible memory by the thread that prepares the draw; a mirror is never moved to device-local memory.
- [Buffer cache bounds](../../../core/libs/prx/libSceAgcDriver/Graphics/src/BufferCache.cpp) (`APS5_BUFFER_CACHE`) - mirrors cover whole 2 MiB zones, merge when a range crosses zones, stop at 64 MiB each and at 1 GiB together, and are evicted least recently used first; none of these bounds is configurable or measured against a title's vertex memory. A merge uploads the merged zones again as draws ask for them. The cache is owned by the recorder and changed under the GPU lock only; a second preparing thread needs a per-block upload lock it does not have.
