# kyty

## add Functional

- [SX downconvert](../../../core/kyty/graphics/host_gpu/renderer/pipeline/pipelineCache.cpp) - `SX_PS_DOWNCONVERT_CONTROL` preserves the eight per-MRT automatic/manual selectors and `SX_PS_DOWNCONVERT` preserves formats 0 through 11. During normal color draw execution, an active target selecting a nonzero manual conversion throws before shader preparation. Speculative preparation declines that state so metadata operations and resolves can reach their existing execution paths; disabled color writes do not consume SX conversions. Manual `NO_CONVERSION` uses the existing SPI export decoding and Vulkan color-buffer conversion; automatic selection retains that existing path rather than reproducing the hardware mapping algorithm. Full RB+ format conversion, its rounding and blend interaction, and `SX_BLEND_OPT_EPSILON`/`SX_BLEND_OPT_CONTROL` remain unsupported. The format selectors are defined in [Mesa gfx103.json](https://github.com/chaotic-cx/mesa-mirror/blob/bb986060e01093a611b962b32fcc90b8d961b706/src/amd/registers/gfx103.json); [PAL's queue preamble](https://github.com/GPUOpen-Drivers/pal/blob/c5e800072a32f68b6ccc4422936d96167c6e0728/src/core/hw/gfxip/gfx9/gfx9QueueContexts.cpp#L1832) establishes selector polarity. [Mesa's RB+ setup](https://github.com/chaotic-cx/mesa-mirror/blob/bb986060e01093a611b962b32fcc90b8d961b706/src/amd/common/ac_formats.c#L805) provides driver-selected compatible format combinations, not a specification of hardware automatic mapping. `CB_COLOR_CONTROL.DISABLE_DUAL_QUAD` alone is not treated as proof that a programmed conversion is inactive. Closes when: nonzero manual conversions and automatic mapping are established against console output, including blending and rounding boundaries. Labels: gpu, tested, windows.
